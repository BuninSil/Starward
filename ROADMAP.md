# ROADMAP — Starward

Основной план этапов и текущее состояние — в [CLAUDE.md](CLAUDE.md) («План этапов», «Корабль в стиле Elite Dangerous», «Этап 6 по шагам»). Здесь — то, что запланировано на потом и пока не делается.

---

## ИИ-фичи (позже)

**Когда:** после того как устаканится основной геймплей: корабль (круиз, посадка, получение), базы, точки интереса, наука и контракты из этапа 6г. До этого ИИ-код не пишем.

**Главные правила:**
- **Игра полностью работает без модели.** У каждой ИИ-фичи есть фолбэк без ИИ: шаблоны или готовые тексты. ИИ только делает их живее.
- **Модель не входит в APK.** Игрок по желанию скачивает её из настроек. Размер APK и автообновление не меняются.
- **Слой ИИ изолирован за интерфейсом.** Его можно выключить или заменить, остальной код от этого не зависит.
- **Никаких токенов внутри APK.** Это правило уже есть в CLAUDE.md. Токен облачного режима вводит сам игрок, он хранится только у него в `user://`.

### Техническое решение (общее для всех этапов)

**Интерфейс `AiTextService`**
- Файл `scripts/ai/ai_service.gd`, асинхронный: `request(kind, context: Dictionary) -> сигнал с текстом или ошибкой`.
- Реализации:
  - `NullAi` — по умолчанию: сразу отдаёт «нет ответа», вызывающий код берёт фолбэк;
  - `LocalAi` — модель на устройстве;
  - `CloudAi` — Hugging Face.
- Выбор реализации — в настройках: «Выкл / На телефоне / Облако».
- Игровой код (миссии, ЦУП, заметки) знает только интерфейс и свой фолбэк.

**Локальная модель**
- Маленькая модель 1–4B в формате GGUF, квантование Q4. Кандидаты с приличным русским: Qwen2.5 1.5B/3B Instruct, Gemma 2/3 2B. Перед выбором проверить лицензии.
- Движок — один из двух:
  - **llama.cpp**: через GDExtension (готовые биндинги для Godot) или через наш Kotlin-плагин `android_plugin/` с JNI-сборкой llama.cpp;
  - **MediaPipe LLM Inference API** (Kotlin, есть GPU-делегат, но свой формат моделей).
- Решение — по прототипу: скорость на Poco X5 (Adreno 619), размер, удобство сборки в CI.
- Генерация только в фоновом потоке и только короткими ответами (лимит токенов). Структура ответа задаётся промптом и проверяется кодом. Невалидный ответ — фолбэк.
- Скачивание модели — переиспользовать загрузчик обновлений (`scripts/autoload/updater.gd`: `HTTPRequest` без потока, сторож зависаний, продолжение после фона).
  - Файл кладётся в `user://ai/`, проверяется по SHA-256.
  - Перед скачиванием показать размер, предупреждение «лучше по Wi-Fi», кнопку «Удалить модель».

**Облачный режим (опционально)**
- Hugging Face Inference Providers, OpenAI-совместимый `https://router.huggingface.co/v1/chat/completions`, с токеном игрока.
- Таймаут, без повторов. Сетевые ошибки молча уходят в лог (как у автообновления), игра берёт фолбэк.

**Контекст для модели**
- Короткий структурированный JSON вместо свободного текста. Например:
  ```
  {"тело":"Луна","высота_км":12.4,"топливо_%":18,"скорость_м_с":1450,"событие":"мало_топлива","миссия":"посадка у базы 2"}
  ```
- Собирается из уже существующих данных: `Vessel`, `Game.bases`, задача автопилота, `flight.where_text()`.

**Общие подзадачи**
- Интерфейс `AiTextService` и `NullAi`.
- Экран в настройках: режим, скачивание и удаление модели, токен облака, кнопка «Проверить».
- Прототип `LocalAi`: замер скорости и памяти на Poco X5, решение «llama.cpp или MediaPipe».
- `CloudAi`.
- Очередь запросов: не больше одного одновременно, низкий приоритет, отмена.
- Отметки в профайлере (`FrameSpikes`) и в логе: время генерации, токены в секунду.

**Общие риски**
| Риск | Что значит | Что делаем |
|---|---|---|
| Вес модели | 1–4B в Q4 — это ~0.8–2.5 ГБ скачивания и места | Не в APK; выбор размера («лёгкая 1.5B / подробная 3B»); скачивание по желанию |
| Память | Модель занимает ~1–3 ГБ ОЗУ рядом с игрой: на телефонах 4–6 ГБ Android может выгрузить игру | Загружать модель только когда фича нужна и выгружать после; на слабых устройствах предлагать облако или «Выкл» |
| Скорость на слабых телефонах | На CPU среднего телефона ~5–20 токенов/с для 1–3B; ответ в 60 токенов — 3–12 с | Короткие ответы; генерация заранее (миссии — при загрузке, заметки — при подлёте); фолбэк, если не успела |
| Перегрев и FPS | Видеокарта уже упирается в 30 FPS, нагрузка на CPU греет телефон и роняет частоты | Генерировать на паузе, на карте, при ускорении времени, на экране загрузки; не во время посадки; ограничение потоков модели (1–2 ядра) |
| Расход батареи | Генерация — минуты полной загрузки CPU | Кэшировать ответы; не генерировать одно и то же повторно; лимит запросов в час |
| Галлюцинации | Маленькая модель выдумывает факты и цифры | Факты только из нашей базы; цифры подставляет код, а не модель; проверка формата ответа |
| Качество русского | Маленькие модели путают падежи и стиль | Выбор модели по тесту на русском; короткие фразы; фолбэк-тексты написаны вручную |
| Сборка | llama.cpp под Android — нативная сборка в CI (NDK), рост времени сборки | Собирать нативную библиотеку отдельным workflow и кэшировать; GDExtension или плагин не тянуть в APK, пока фича выключена |
| Сеть и приватность (облако) | Токен игрока, лимиты бесплатного уровня HF, задержки | Токен только в `user://`, не в логах; понятная ошибка «лимит исчерпан»; облако — только по явному выбору |

### Этап 1. Генерация миссий

**Что:** задания вида:
- «доставить модуль на орбиту»;
- «найти место посадки со льдом»;
- «спасти космонавта с оборванным тросом»;
- «привезти образец с Фобоса» и т.п.

Миссии используют реальные объекты игры: тела из `SolarSystem`, базы игрока, точки интереса (6г). ИИ пишет название, брифинг и диалог диспетчера. Цели и проверки задаёт код.

**Обязательный фолбэк:** генератор миссий по шаблонам, без ИИ. Игра полностью играбельна только с ним.

**Подзадачи**
1. Модель миссии `scripts/game/missions.gd`:
   - тип, цель (тело, координаты, высота, предмет);
   - условия выполнения и провала;
   - награда, срок.
   Сохранение в `Game` рядом с `bases`.
2. Генератор по шаблонам: таблица типов, параметры из реальных данных:
   - тела и их орбиты;
   - ресурсы (`Resources.at`);
   - базы (`Game.bases`);
   - доступный Δv игрока.
   Отсев невыполнимого: по Δv и наличию атмосферы для парашюта.
3. Проверка выполнения в полёте:
   - события `Vessel` (посадка, орбита, SOI);
   - стыковка с базой (`nearby_base`);
   - груз (`Inventory`).
4. Экран миссий: список, брифинг, «Принять». Отметка цели на карте (`TrajectoryView`).
5. Шаблонная миссия «спасти космонавта»: второй космонавт с оборванным тросом, физика EVA (`tether.gd`, `astronaut`) уже есть.
6. ИИ-слой поверх шаблона: модели передаются тип и параметры (JSON), она возвращает название, брифинг на 2–3 предложения и реплики диспетчера.
   - Числа и цели в тексте не от модели: код вставляет их сам.
   - Проверка: длина, нет чужих тел и цифр.
7. Генерация заранее: пачка из 3–5 миссий при загрузке или на паузе, кэш в сохранении.

**Зависимости от текущего кода**
- `SolarSystem`, `CelestialBody` — реальные тела.
- `Bases` — базы игрока.
- `Resources` — ресурсы.
- `Vessel`, `Autopilot`/`Planner` — оценка достижимости, Δv.
- `Game` — сохранения.
- Карта (`TrajectoryView`) — метки.
- EVA (`tether.gd`, `astronaut`).
- Этап 6г (точки интереса, контракты) — миссии во многом его расширение. Делать после 6г.

**Риски**
- Невыполнимые миссии. Отсев шаблонным генератором до ИИ.
- ИИ-текст противоречит целям. Цели и цифры только из кода, модель пишет лишь «обёртку».
- Повторяемость шаблонов без ИИ. Много шаблонов и вариаций фраз.
- Вес, скорость, перегрев — см. общие риски. Генерация на паузе и в загрузке закрывает почти всё.

### Этап 2. ЦУП / бортовой компьютер

**Что:** персонаж-диспетчер с характером (имя, манера речи, лёгкий юмор). Комментирует полёт и реагирует на события:
- мало топлива;
- жёсткая или неудачная посадка;
- выход в открытый космос;
- обрыв троса;
- вход в атмосферу и перегрев;
- выход на орбиту;
- переход в сферу влияния Луны.

На вход получает короткий структурированный контекст: топливо, орбита, цель миссии, событие.

**Подзадачи**
1. Шина игровых событий `GameEvents` (сигналы), куда уже генерируемое пишет одно и то же:
   - `destroyed`, `wrecked`, `burned_off`, `stage`;
   - SOI, посадка, EVA, трос;
   - топливо ниже порога.
   Сейчас эти события разбросаны: `flight.message`, сигналы `Vessel`, `hud.toast`.
2. Фолбэк: таблица готовых реплик по событию и состоянию, несколько вариантов на событие, характер задан стилем текста. Без ИИ ЦУП уже работает.
3. Окно ЦУП в HUD: аватар, строка реплики, история последних сообщений; кнопка «Тише / Выкл». Озвучка — позже и отдельно: TTS тяжёлый, решать отдельно.
4. ИИ-режим: событие и контекст (JSON) плюс системный промпт характера. Ответ в 1–2 предложения. Если не уложился в N секунд — реплика из таблицы.
5. Защита от спама: не чаще раза в X секунд, приоритеты событий (авария важнее «вышли на орбиту»), не повторять одно и то же.
6. Генерация заранее: «предсказуемые» реплики (подлёт к телу, скорая посадка) готовить во время круиза или ускорения времени.

**Зависимости от текущего кода**
- Сигналы `Vessel` (`destroyed`, `wrecked`, `burned_off`).
- `flight.message`, `flight_hud.toast` — нынешние уведомления.
- Данные полёта для контекста: `OrbitMath.elements`, `Vessel.total_delta_v`, `heat_fraction`, тросы EVA.
- Задача автопилота: `Autopilot.status`.
- Миссия из этапа 1, если есть.

**Риски**
- **Задержка.** Реакция на аварию через 5–10 с выглядит глупо. Срочные события только из таблицы, ИИ — для неспешных реплик.
- **Перегрев и FPS** в самые нагруженные моменты (посадка, вход в атмосферу). Во время этих фаз ИИ не генерирует, только таблица.
- **Надоедливость.** Частота, «Тише», выключение.
- **Неверные цифры от модели.** Числа подставляет код, модель не пересчитывает.

### Этап 3. Научные заметки

**Что:** при посадке, выходе на орбиту или пролёте рядом с телом — 1–3 кратких реальных факта о планете или спутнике. Факты берутся из заранее подготовленной базы, ИИ только подаёт их живым текстом с учётом ситуации: «Ты над Морем Спокойствия, где сели Армстронг и Олдрин…».

**Подзадачи**
1. База фактов `data/facts/<id>.json`:
   - на каждое тело 15–40 коротких проверенных фактов (по-русски, с источником: NASA, ESA);
   - теги: «геология», «история исследований», «атмосфера», «рекорд»;
   - для крупных тел — привязка к районам по широте и долготе (моря Луны, Олимп на Марсе).
   Текстовые файлы в репо. Источник фактов — в `CREDITS.md`.
2. Выбор факта по ситуации: тело, район (широта и долгота уже считаются — `lat_lon`), событие (посадка, орбита, пролёт), ещё не показанный (учёт в сохранении).
3. Фолбэк: показать факт как есть, карточкой «Научная заметка».
4. ИИ-режим: факт плюс ситуация (JSON). Модель возвращает 1–2 предложения живым текстом, не добавляя новых фактов. Проверка: ключевые числа и имена из факта на месте, лишних нет; иначе — исходный факт.
5. Связка с наукой (6г): заметка открывается за эксперимент или посадку, «журнал открытий».

**Зависимости от текущего кода**
- `SolarSystem` и `CelestialBody` (id тел).
- `CelestialBody.lat_lon` — район посадки.
- События посадки, орбиты и SOI (`Vessel`).
- `Game` — учёт показанного.
- Этап 6г — наука, журнал.

**Риски**
- **Галлюцинации.** Модель только перефразирует факт из базы, проверка совпадения имён и чисел.
- **Объём ручной работы по базе фактов.** Начать с Земли, Луны и Марса, остальное по мере надобности.
- **Скорость и перегрев.** Заметку готовить при подлёте (за минуты до события), показывать готовую.
- **Сеть в облачном режиме.** Нет ответа — показывается сам факт.

### Порядок внутри ИИ-фич
0. Интерфейс `AiTextService` и `NullAi`, экран настроек, шина событий `GameEvents`. Это полезно и без ИИ.
1. Фолбэки всех трёх этапов (шаблонные миссии, таблица реплик ЦУП, база фактов). Это полноценные фичи сами по себе.
2. Прототип `LocalAi` на Poco X5: замеры, выбор движка и модели.
3. ИИ-слой поверх фолбэков: заметки (самый безопасный) → ЦУП (неспешные реплики) → миссии.
4. `CloudAi` как опция.
