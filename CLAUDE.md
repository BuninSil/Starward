# CLAUDE.md — Starward

Мобильная 3D-игра для Android: космический симулятор в духе Spaceflight Simulator, но в 3D, ближе к реализму, но играбельно.
Рабочее название — **Starward** (финальное название ещё не выбрано, в коде держим его в одном месте: `application/config/name` в `project.godot`).

Разработка идёт **полностью без ПК**: пользователь тестирует только на телефоне, APK собирается в GitHub Actions.
Claude игру не видит — опираемся на описания и скриншоты пользователя.

## Стек
- Godot 4 (последняя стабильная 4.x, сейчас **4.7.2**), GDScript, рендерер **Mobile** (фолбэк на OpenGL для устройств без Vulkan).
- Сцены и ресурсы — **только текстовые** (`.tscn` / `.tres`), чтобы править их без редактора. Бинарные `.scn`/`.res` запрещены.
- Целевые устройства — средние Android-смартфоны. Цель — стабильные 30+ FPS.
- Версия Godot задаётся в одном месте: `env.GODOT_VERSION` в `.github/workflows/build.yml`. При смене версии обновить и `android_plugin/` (версия `godot-lib`, AGP, Kotlin — сверять с `platform/android/java/app/config.gradle` той же версии Godot).

## Сборка и релизы (GitHub Actions)
- На каждый пуш в `main` — сборка APK headless-экспортом Godot (`.github/workflows/build.yml`).
- Подпись — **одним постоянным keystore**. Сейчас он лежит открыто в репо (`signing/release.keystore` + `signing/keystore.properties`, решение пользователя). Если заданы Secrets `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` — CI берёт их, но там обязан лежать **тот же** ключ.
- Отпечаток сертификата закреплён в `signing/cert_sha256.txt`; CI падает, если APK подписан другим ключом.
- **Никогда не генерировать новый ключ** — ни в CI, ни где-либо ещё. Иначе обновления не встанут поверх старой версии. Подробности — `docs/KEYSTORE.md`.
- `versionCode = github.run_number`, `versionName = 0.1.<run_number>`.
- После сборки — GitHub Release с тегом `v0.1.<run_number>`, APK как asset, в описании — список коммитов с прошлого релиза.

## Автообновление
- При запуске игра запрашивает `https://api.github.com/repos/BuninSil/Starward/releases/latest` и сравнивает versionCode из тега (`v0.1.N` → `N`) с текущим (`starward/build/version_code` в `project.godot`, CI подставляет при сборке).
- Есть новая версия — окно «Доступно обновление vX» с текстом релиза, кнопки «Обновить» / «Позже».
- «Обновить»: скачать APK в кэш приложения с прогрессом и запустить системную установку через package installer (FileProvider + `REQUEST_INSTALL_PACKAGES`) — минимальный Android-плагин на Kotlin (`android_plugin/` → `addons/starward_updater/`).
- Фолбэки по порядку: плагин → `OS.shell_open(локальный apk)` (FileProvider самого Godot) → открыть ссылку на APK в браузере.
- **Никаких токенов GitHub внутри APK.** Репозиторий с релизами должен быть публичным.
- Проверка один раз за запуск; сетевые ошибки молча игнорируются (только в лог).
- В дебаг-меню — кнопка «Проверить обновление сейчас».

## Физика — делаем честно
- Орбитальная механика — **patched conics (SOI)**: в каждый момент на корабль действует гравитация одного тела. Никакого n-body.
- Орбитальное состояние — в 64-битных float, **отдельно от сцены**. **Floating origin**: мир сдвигается вокруг активного корабля.
  - Важно: `Vector3` в GDScript — 32-битный (стандартная сборка Godot). Для орбитального состояния использовать свои 64-битные структуры (тройки `float` — в GDScript `float` 64-битный), в сцену переводить только относительные координаты.
- Ракетная физика: сухая масса + топливо, тяга, удельный импульс (атмосфера/вакуум), уравнение Циолковского, оставшийся Δv по ступеням.
- Атмосфера: экспоненциальная плотность по высоте, сопротивление по площади сечения и скорости, простой нагрев при входе (перегрев = разрушение детали).
- Солнечная система (`scripts/sim/solar_system.gd`): корень — Солнце; 8 планет с элементами J2000 (эпоха t=0 = 2000-06-21), Луна, Фобос/Деймос, позже крупные спутники Юпитера. Инерциальная система — экватор Земли (ось Y), орбиты планет заданы в эклиптике и повёрнуты на 23.44° (`orbit_tilt`). Все тела вращаются вокруг Y (упрощение). Земля в коде сцены — `flight.home`, Солнце — `flight.root_body`. Реальные наклоны и эксцентриситеты. Размеры и расстояния уменьшены в 10 раз, гравитация подстроена так, чтобы орбиты и ощущения остались правдоподобными. Time warp обязателен.

## Упрощаем — НЕ делать без прямого запроса пользователя
- Никакой аэродинамики формы деталей, никакого изгиба/вибраций конструкции. Ракета жёсткая.
- Решение пользователя: **разрушение по модулям** и простая аэродинамика без формы. `Vessel._impact`: каждая ступень со своим пределом удара (`crash_tolerance`: баки 7, ноги 12, капсула 22 м/с), смятые ступени гасят энергию, разбитая ступень взрывается и исчезает (`wrecked` → `flight._explosion`). Конец игры — только гибель капсулы. `aero_accel`: стопка устойчива носом по потоку (со стабилизаторами `fins` сильнее), одиночная капсула — дном вперёд; `side_load` > `AERO_BREAK` в плотном воздухе — стопка разваливается, капсула остаётся. Тест: `tests/test_damage.gd`.
- Никакого n-body, прецессии, солнечного ветра и прочего.
- Никакой процедурной генерации новых миров.
- **Не «улучшать реализм» по своей инициативе.** Если кажется, что надо усложнить — спросить.

## Автопилот (решение пользователя)
- Задачи + цепочки: панель «Автопилот» — задача с параметром («Пуск» сразу или «+ в цепочку»), пресет «Полная миссия».
- Автопилоту можно всё, что умеет игрок: ориентация, газ, ступени, ускорение времени, манёвры. Любой ручной ввод его выключает.
- Код: `scripts/sim/autopilot.gd` (очередь задач и пресеты) + `scripts/sim/autopilot/ap_*.gd` (задачи). Расчёты манёвров — `Planner` в фоновом потоке (`ApPlan`), без обращения к сцене и автозагрузкам.
- Готовые ракеты (до конструктора): `Vessel.DESIGNS` — «Орбита» и «Лунная ракета» (посадочная ступень с ногами `legs`, взлётная ступень); выбор на титульном экране и в дебаг-меню.
- Посадка на тело без атмосферы: `ApPlan "moon_deorbit"` (сход к освещённому месту) + `ApDescent`; взлёт: `ApLiftoff` (посадочная ступень остаётся) + `ApAscent`.
- Межпланетные перелёты: `Planner.transfer_window` (окно Гомана + перебор Ламберта), `plan_interplanetary` (отлёт в плоскости парковочной орбиты), `plan_helio_correction` (Ламберт в пути), затем `peri_correction` у цели и захват. Цепочки `Autopilot.tasks_planet` / `tasks_planet_home`. Тест: `tests/test_planet.gd`.
- В `scripts/sim/` не использовать автозагрузки (`Log` и т.п.) — классы компилируются в headless-тестах раньше них; для лога достаточно `print("[I] ...")`.

## Помощники для игрока
- Удержание ориентации: прогрейд, ретрогрейд, нормаль, антинормаль, радиально, на цель.
- Простые манёвры: точка на орбите + ползунки Δv, предпросмотр новой траектории.
- Подсказка окна перелёта к выбранной планете.

## Конструктор
- Детали по сетке: в стопку и радиально (симметрия 2/3/4 максимум).
- Стартовые детали: капсула, баки 3 размеров, 2–3 двигателя, декаплер, парашют, ноги, маневровые движки, люк.
- Ступени задаются порядком декаплеров.

## EVA
- Космонавт выходит через люк.
- Ранец — полные 6 степеней свободы:
  - перемещение: левый джойстик (вперёд/назад, влево/вправо) + кнопки вверх/вниз;
  - вращение: свайп по правой половине экрана (тангаж/рыскание), кнопки крена;
  - кнопка «стабилизация» — гасит вращение;
  - кнопка «гасить скорость относительно корабля»;
  - кнопка «повернуться к кораблю».
- Перемещение и вращение расходуют топливо ранца. Кислород — отдельная полоска.
- Трос: физически — ограничение дистанции (distance joint) до точки крепления; визуально — Verlet-цепочка ~25 сегментов, на физику не влияет. Коллизии троса с кораблём не нужны.
- Лебёдка (подтянуться), отстёгивание. Если корабль даёт тягу и натяжение троса превышает порог — трос рвётся.
- На поверхности планет: ходьба, прыжок, гравитация к центру тела, трос не используется.

## Планеты
- Сфера с картой высот и текстурой (можно генерировать шумом под стиль планеты). Позже — LOD рельефа при подлёте.
- Атмосфера — простой шейдер рассеивания + упрощённый вариант для слабых телефонов.
- Грунт вблизи (решение пользователя: реализм по фото Apollo / Curiosity): `shaders/planet_surface.gdshader` — реальное альбедо тела (`surface_style()` в `planet_view.gd`), 4 материала на тело со смешиванием по высоте, стохастический тайлинг, мелкие кратеры-декали, освещение реголита (Ломмель–Зеелигер) на телах без атмосферы. Кратеры ≥ 3 м — в карте высот (`Terrain.set_crater_field`, молодые со светлыми лучами). Камни/галька/пылевые наносы — MultiMesh (`_compute_rocks`).
- Ракеты (решение пользователя: чистый стиль SFS/KSP): `scripts/flight/rocket_view.gd` — детали из профилей вращения с фасками, окраска `shaders/hull.gdshader` (полосы, швы, окна и люк рисуются шейдером, металл/фольга с фейковыми отражениями через global uniforms `env_*`), переходник над лунным модулем, стартовый комплекс `launch_pad.gd`. Проверка всех деталей со всех сторон — дебаг-меню «Витрина деталей» (`parts_showcase.gd`). Порядок вершин в `_lathe`: по часовой = лицевая.
- Космонавт: свой процедурный скафандр в духе EMU с анимацией по суставам (`scripts/eva/astronaut_model.gd`), люк капсулы открывается при выходе.
- Звуки синтезируются кодом при старте полёта (`scripts/flight/sound_fx.gd`, фоновый поток): двигатель (воздух/вакуум), ветер, RCS, отстрел, удар, люк, шаги, дыхание.
- Ночное освещение: навигационные огни, строб, прожекторы и тёплая подсветка на капсуле (`rocket_view._build_lights`), лампы на шлеме (`astronaut_model.lamps`); у земли (`rocket.ground_agl` < ~25 м) навигационные огни дают слабое цветное пятно на грунт (вторая лампа только на слой грунта, `SPILL_*`); включаются по `rocket.night` (солнце за горизонтом или корабль в тени планеты — тогда солнечный свет гасится).
- Парашют — купол из клиньев с шейдером ткани (`shaders/chute.gdshader`), после посадки заваливается и ложится.
- Вход в атмосферу (`Vessel._step_heating`): поток Саттона–Грейвса на ведущую часть, температура обшивки; теплозащита только у капсулы дном вперёд, голая нижняя ступень перегревается и отваливается (`burned_off`), носом/боком — сгорает. Визуал: плазма (`shaders/plasma.gdshader`), нагар и раскалённая обшивка (`scorch`/`glow` в `hull.gdshader`), предупреждение в HUD.
- Дым/пыль/искры — своя система частиц в double относительно тела (`scripts/flight/fx_particles.gd`, MultiMesh): облака у грунта от двигателя (в атмосфере и на реголите — густые низкие), столб дыма при подъёме, след при входе, облачко при касании, подсветка пламенем и прожекторами; выжженное пятно на грунте (`shaders/scorch.gdshader`). Свет пламени на ракете (`rocket_view._engine_light`) и на грунте (`flight._flame_light`).
- Пресет графики «высокая/низкая» (`scripts/flight/graphics.gd`, дебаг-меню): на низкой — без детального грунта, теней и гальки.

## Производительность (телефон, рендерер Mobile)
- В Mobile нет depth prepass: перекрытое шейдится зря. Детальный грунт (`render_priority` 1), камни и площадка (2) рисуются раньше шара планеты, чтобы шар под ними отсекался по глубине.
- Много мелкой статики → `MeshMerge.merge` (один меш на материал): стартовый стол, обшивка ступеней, суставы космонавта. Камни запечены по клеткам `ROCK_CHUNK` (`_with_rock_chunks`, объектные координаты в CUSTOM0/1), чтобы отсекались вне кадра и вне дальности теней.
- Далёкие тела — лёгкий шар (`_globe_lo`), когда меньше ~60 px.
- 3D рендерится в 60% с апскейлом FSR 1.0 (`scaling_3d/*.mobile` в `project.godot`): выглядит как прежние 75% билинейно, пикселей на треть меньше. Отдельный поток рендера (`thread_model=2`) не включать — Godot пишет, что нестабилен.
- Грунт на слое рендера 2 (`GROUND_LAYER`): мелкие лампы (навигационные огни) его не перебирают (`light_cull_mask = 1`).
- Небо полёта — полноэкранный квад `shaders/sky_quad.gdshader` (render_priority −128, дальняя плоскость), не ресурс `Sky`: Sky перерисовывает куб окружения при каждой смене параметров (у нас — каждый кадр), на телефоне это было очень дорого. Фон окружения — `BG_COLOR`.
- Грунт: цвета/веса/нормали в половинной точности (макрос `LP` = mediump в `planet_surface.gdshader`; координаты, UV и хэши — полная). Для сравнения в профайлере есть вариант с `#define LP highp`. По замеру пользователя «детали вблизи» — главная цена грунта.
- До 120 FPS: `application/run/max_fps=120`, `Graphics.apply_fps()`: плагин `requestRefreshRate(maxHz)` выбирает лучший режим экрана (120/90/60 — что есть у телефона), потолок FPS = выбранная частота; в настройках «Частота кадров»: авто / 60 / 30. Симуляция — фиксированные 60 Гц (`DT`), поэтому `flight._process` рисует кадр между двумя тиками (интерполяция `sim_time`, `vessel.pos`, `attitude`, трансформ космонавта → `_astro_xf`, смещение модели) и в конце возвращает состояние. Новый код отрисовки в EVA — брать `_astro_xf`, а не `astronaut.global_transform`.
- Дым: форма клубов (7 вариантов) запечена в атлас `fx_particles._atlas` (строится в фоне при старте игры, `prepare()`), фрагмент — одна выборка; клуб — восьмиугольник, подсветка пламенем/прожекторами и высота над грунтом — в вершинном шейдере.
- Профайлер в дебаг-меню: CPU/GPU мс, draw calls, выключатели фич и разрешения — первым делом просить у пользователя его цифры.
- Горячие циклы GDScript — без аллокаций `DVec3` (частицы `fx_particles.gd` пишут сразу буфер MultiMesh; траектория — эллипс в float, `Trajectory._Ellipse`).
- Замеры: Vulkan lavapipe под xvfb с `--rendering-method mobile` (иначе Forward+), сравнение скринов до/после.

## Управление
- Только тач. Крупные кнопки, газ ползунком, джойстик для ориентации, переключение карта/полёт одной кнопкой.
- Главное меню (`scripts/ui/boot.gd`): «Играть», карточки ракет, «Ракеты» (витрина), «Настройки» (графика, обновления, консоль, лог), «Выход»; фон — Земля NASA (`shaders/title_earth.gdshader`) и Луна. Отладка спрятана в настройки.
- Android «Назад» (`quit_on_go_back=false`): в полёте и EVA — меню паузы, в главном меню — закрыть панель/выйти.
- Ракета вращается вокруг центра масс (`Vessel.com_height()`), камера смотрит в него.

## Отладка (обязательна с самого начала)
- Оверлей: FPS, версия, высота, скорость, апогей/перигей, текущее SOI, координаты.
- Внутриигровая консоль ошибок + кнопка «Скопировать лог в буфер». Весь лог идёт через автозагрузку `Log` (`scripts/autoload/log.gd`), а не голый `print`.
- Дебаг-меню: бесконечное топливо, телепорт на орбиту/поверхность любого тела, сброс, ускорение времени, проверка обновления.

## Как работаем
- Маленькие шаги. Каждый рабочий шаг — отдельный коммит с понятным сообщением.
- Пушим **прямо в `main`** (разрешено пользователем): каждый пуш = новый релиз, который прилетает в игру автообновлением. Поэтому в `main` уходит только то, что прошло локальную проверку.
- После каждого шага — коротко пользователю: что изменилось и **что конкретно проверить на телефоне**.
- Перед крупными архитектурными изменениями — спросить.
- Ассеты только свои (сгенерированные кодом, примитивы) или CC0 / NASA public domain; источник — в `CREDITS.md`.
- Код и комментарии — по-английски, тексты в игре и общение — по-русски.
- **Сообщения коммитов — по-русски** (из них собирается описание релиза, которое игрок видит в окне обновления).
- Локальная проверка (если в окружении есть собранный Godot): `godot --headless --path . --import` и запуск сцен без ошибок парсинга до пуша.

### Этап 6 по шагам (решение пользователя: экономика и постройки в духе No Man's Sky, но с честными орбитами)
- **6а. Фундамент:** сохранения (сейчас их нет) + инвентарь космонавта (малый) и корабля (больше).
- **6б (сделано):** `scripts/game/resources.gd` — богатство льда/руды/реголита по телу и координатам (детерминированный шум, лёд у полюсов), `Crafting` — рецепты (лёд → кислород/топливо, руда → металл → детали), заправка ракеты и пополнение баллона; бур космонавта на поверхности (`flight._drill_tick`, кнопка «Бур»), вкладка «Производство» в окне груза. Тест: `tests/test_resources.gd`.
- **6б. Ресурсы и крафт (план):** ресурсы по телам (лёд, руда, реголит, газы; на каждом теле свои), добыча буром космонавта, крафт: топливо, кислород, детали, модули базы.
- **6в. Модульные базы:** модули по сетке (жилой, склад, солнечная панель, батарея, бур, переработчик лёд → топливо/кислород, заправка ракеты, посадочная площадка); ставятся стоя на поверхности, стыкуются к соседним; на базе можно дозаправиться и лететь дальше.
- **6г. Цель:** точки интереса, наука, дерево технологий, контракты, лор (ниже).
- Управление кораблём остаётся ракетным (не NMS-полёт): цикл «прилетел → добыл → заправился → улучшил → полетел дальше». Этап 7 (конструктор) — сборка и улучшение своего корабля из открытых деталей.

### Геймплей на планетах (этап 6, решение пользователя)
Цель: дать игроку причину летать по планетам. Цикл: полетел → нашёл → добыл/изучил → прокачался → полетел дальше.
- Точки интереса: на каждом теле 10–30 штук (аномалии, обломки зондов, залежи льда/руды, гейзеры, пещеры — по тематике тела). Генерируются детерминированно из seed тела. Видны орбитальным сканером, на поверхности — маркер и расстояние.
- Наука: эксперименты (образец грунта, замер атмосферы, фото, сканирование). Уникальные для каждого тела и биома. Очки науки открывают новые детали в дереве технологий.
- Ресурсы: лёд, руда, реголит. Добываются буром космонавта (немного) или буром базы/ровера (много).
- База: модули по сетке на поверхности — жилой, солнечная панель, батарея, бур, переработчик (лёд → топливо), заправочный шланг. Без сложной логистики.
- Ровер: собирается в конструкторе из колёс и корпуса, ездит по рельефу, может нести бур и экспериментальное оборудование.
- Контракты: простые задания (вывести на орбиту, высадиться, привезти образец), награда — валюта для покупки деталей.
- Лор: записки и сигналы в некоторых точках интереса, складываются в одну сюжетную линию до края системы.
- Никакой фауны/флоры и процедурных существ на других телах (живое — только на Земле, этап 8).
- Всё рассчитано на мобильную производительность: объекты точек интереса подгружаются только рядом с игроком.

Внутри этапа 1 порядок: CI + подпись + пустая сцена с версией → автообновление (проверить, что новая версия прилетает в игре) → только потом физика и ракета.
