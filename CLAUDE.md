# CLAUDE.md — Starward

Мобильная 3D-игра для Android: космический симулятор в духе Spaceflight Simulator, но в 3D, ближе к реализму, но играбельно.
Рабочее название — **Starward** (финальное название ещё не выбрано, в коде держим его в одном месте: `application/config/name` в `project.godot`).

Разработка идёт **полностью без ПК**: пользователь тестирует только на телефоне, APK собирается в GitHub Actions.
Claude игру не видит — опираемся на описания и скриншоты пользователя.

## Стек
- Godot 4 (последняя стабильная 4.x, сейчас **4.7.2**), GDScript, рендерер **Mobile** (фолбэк на OpenGL для устройств без Vulkan).
- Сцены и ресурсы — **только текстовые** (`.tscn` / `.tres`), чтобы править их без редактора. Бинарные `.scn`/`.res` запрещены.
- Целевые устройства — средние Android-смартфоны. Цель — стабильные 30+ FPS.
- Версия Godot задаётся в одном месте: `env.GODOT_VERSION` в `.github/workflows/build.yml`. При смене версии обновить и `android_plugin/` (версия `godot-lib`, AGP, Kotlin — сверять с `platform/android/java/app/config.gradle` той же версии Godot).

## Сборка и релизы (GitHub Actions)
- На каждый пуш в `main` — сборка APK headless-экспортом Godot (`.github/workflows/build.yml`).
- Подпись — **одним постоянным keystore**. Сейчас он лежит открыто в репо (`signing/release.keystore` + `signing/keystore.properties`, решение пользователя). Если заданы Secrets `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` — CI берёт их, но там обязан лежать **тот же** ключ.
- Отпечаток сертификата закреплён в `signing/cert_sha256.txt`; CI падает, если APK подписан другим ключом.
- **Никогда не генерировать новый ключ** — ни в CI, ни где-либо ещё. Иначе обновления не встанут поверх старой версии. Подробности — `docs/KEYSTORE.md`.
- `versionCode = github.run_number`, `versionName = 0.1.<run_number>`.
- После сборки — GitHub Release с тегом `v0.1.<run_number>`, APK как asset, в описании — список коммитов с прошлого релиза.

## Автообновление
- При запуске игра запрашивает `https://api.github.com/repos/BuninSil/Starward/releases/latest` и сравнивает versionCode из тега (`v0.1.N` → `N`) с текущим (`starward/build/version_code` в `project.godot`, CI подставляет при сборке).
- Есть новая версия — окно «Доступно обновление vX» с текстом релиза, кнопки «Обновить» / «Позже».
- «Обновить»: скачать APK в кэш приложения с прогрессом и запустить системную установку через package installer (FileProvider + `REQUEST_INSTALL_PACKAGES`) — минимальный Android-плагин на Kotlin (`android_plugin/` → `addons/starward_updater/`).
- Фолбэки по порядку: плагин → `OS.shell_open(локальный apk)` (FileProvider самого Godot) → открыть ссылку на APK в браузере.
- **Никаких токенов GitHub внутри APK.** Репозиторий с релизами должен быть публичным.
- Проверка один раз за запуск; сетевые ошибки молча игнорируются (только в лог).
- В дебаг-меню — кнопка «Проверить обновление сейчас».

## Физика — делаем честно
- Орбитальная механика — **patched conics (SOI)**: в каждый момент на корабль действует гравитация одного тела. Никакого n-body.
- Орбитальное состояние — в 64-битных float, **отдельно от сцены**. **Floating origin**: мир сдвигается вокруг активного корабля.
  - Важно: `Vector3` в GDScript — 32-битный (стандартная сборка Godot). Для орбитального состояния использовать свои 64-битные структуры (тройки `float` — в GDScript `float` 64-битный), в сцену переводить только относительные координаты.
- Ракетная физика: сухая масса + топливо, тяга, удельный импульс (атмосфера/вакуум), уравнение Циолковского, оставшийся Δv по ступеням.
- Атмосфера: экспоненциальная плотность по высоте, сопротивление по площади сечения и скорости, простой нагрев при входе (перегрев = разрушение детали).
- Солнечная система: Солнце, 8 планет, Луна, Фобос/Деймос, позже крупные спутники Юпитера. Реальные наклоны и эксцентриситеты. Размеры и расстояния уменьшены в 10 раз, гравитация подстроена так, чтобы орбиты и ощущения остались правдоподобными. Time warp обязателен.

## Упрощаем — НЕ делать без прямого запроса пользователя
- Никакой аэродинамики формы деталей, никакого изгиба/вибраций конструкции. Ракета жёсткая, ломается только от удара или перегрева.
- Никакого n-body, прецессии, солнечного ветра и прочего.
- Никакой процедурной генерации новых миров.
- **Не «улучшать реализм» по своей инициативе.** Если кажется, что надо усложнить — спросить.

## Автопилот (решение пользователя)
- Задачи + цепочки: панель «Автопилот» — задача с параметром («Пуск» сразу или «+ в цепочку»), пресет «Полная миссия».
- Автопилоту можно всё, что умеет игрок: ориентация, газ, ступени, ускорение времени, манёвры. Любой ручной ввод его выключает.
- Код: `scripts/sim/autopilot.gd` (очередь задач и пресеты) + `scripts/sim/autopilot/ap_*.gd` (задачи). Расчёты манёвров — `Planner` в фоновом потоке (`ApPlan`), без обращения к сцене и автозагрузкам.
- Готовые ракеты (до конструктора): `Vessel.DESIGNS` — «Орбита» и «Лунная ракета» (посадочная ступень с ногами `legs`, взлётная ступень); выбор на титульном экране и в дебаг-меню.
- Посадка на тело без атмосферы: `ApPlan "moon_deorbit"` (сход к освещённому месту) + `ApDescent`; взлёт: `ApLiftoff` (посадочная ступень остаётся) + `ApAscent`.
- В `scripts/sim/` не использовать автозагрузки (`Log` и т.п.) — классы компилируются в headless-тестах раньше них; для лога достаточно `print("[I] ...")`.

## Помощники для игрока
- Удержание ориентации: прогрейд, ретрогрейд, нормаль, антинормаль, радиально, на цель.
- Простые манёвры: точка на орбите + ползунки Δv, предпросмотр новой траектории.
- Подсказка окна перелёта к выбранной планете.

## Конструктор
- Детали по сетке: в стопку и радиально (симметрия 2/3/4 максимум).
- Стартовые детали: капсула, баки 3 размеров, 2–3 двигателя, декаплер, парашют, ноги, маневровые движки, люк.
- Ступени задаются порядком декаплеров.

## EVA
- Космонавт выходит через люк.
- Ранец — полные 6 степеней свободы:
  - перемещение: левый джойстик (вперёд/назад, влево/вправо) + кнопки вверх/вниз;
  - вращение: свайп по правой половине экрана (тангаж/рыскание), кнопки крена;
  - кнопка «стабилизация» — гасит вращение;
  - кнопка «гасить скорость относительно корабля»;
  - кнопка «повернуться к кораблю».
- Перемещение и вращение расходуют топливо ранца. Кислород — отдельная полоска.
- Трос: физически — ограничение дистанции (distance joint) до точки крепления; визуально — Verlet-цепочка ~25 сегментов, на физику не влияет. Коллизии троса с кораблём не нужны.
- Лебёдка (подтянуться), отстёгивание. Если корабль даёт тягу и натяжение троса превышает порог — трос рвётся.
- На поверхности планет: ходьба, прыжок, гравитация к центру тела, трос не используется.

## Планеты
- Сфера с картой высот и текстурой (можно генерировать шумом под стиль планеты). Позже — LOD рельефа при подлёте.
- Атмосфера — простой шейдер рассеивания + упрощённый вариант для слабых телефонов.

## Управление
- Только тач. Крупные кнопки, газ ползунком, джойстик для ориентации, переключение карта/полёт одной кнопкой.

## Отладка (обязательна с самого начала)
- Оверлей: FPS, версия, высота, скорость, апогей/перигей, текущее SOI, координаты.
- Внутриигровая консоль ошибок + кнопка «Скопировать лог в буфер». Весь лог идёт через автозагрузку `Log` (`scripts/autoload/log.gd`), а не голый `print`.
- Дебаг-меню: бесконечное топливо, телепорт на орбиту/поверхность любого тела, сброс, ускорение времени, проверка обновления.

## Как работаем
- Маленькие шаги. Каждый рабочий шаг — отдельный коммит с понятным сообщением.
- Пушим **прямо в `main`** (разрешено пользователем): каждый пуш = новый релиз, который прилетает в игру автообновлением. Поэтому в `main` уходит только то, что прошло локальную проверку.
- После каждого шага — коротко пользователю: что изменилось и **что конкретно проверить на телефоне**.
- Перед крупными архитектурными изменениями — спросить.
- Ассеты только свои (сгенерированные кодом, примитивы) или CC0 / NASA public domain; источник — в `CREDITS.md`.
- Код и комментарии — по-английски, тексты в игре и общение — по-русски.
- Локальная проверка (если в окружении есть собранный Godot): `godot --headless --path . --import` и запуск сцен без ошибок парсинга до пуша.

## План этапов
1. Каркас проекта, CI со сборкой и релизами, автообновление, Земля, готовая ракета без конструктора, взлёт, выход на орбиту, линия орбиты, time warp, дебаг-оверлей.
2. Луна, переходы SOI, манёвры, перелёт и возврат.
3. EVA: выход, ранец, трос, кислород, возврат в корабль.
4. Посадка на тело и ходьба по поверхности.
5. Остальная Солнечная система, атмосферы, нагрев.
6. Конструктор ракет.
7. Графика, звук, полировка, меню.

Внутри этапа 1 порядок: CI + подпись + пустая сцена с версией → автообновление (проверить, что новая версия прилетает в игре) → только потом физика и ракета.
