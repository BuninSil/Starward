# Ключ подписи APK

Android ставит обновление поверх старой версии, только если оба APK подписаны **одним и тем же ключом**.
Ключ у проекта один и навсегда. Его отпечаток зафиксирован в `signing/cert_sha256.txt`, и CI падает, если APK подписан чем-то другим.

## Где ключ сейчас

`signing/release.keystore` + `signing/keystore.properties` (alias и пароль) — **открыто в публичном репо**. Это осознанный временный выбор: ноль ручных действий.
Минус: любой, кто скачает репо, может подписать APK, который Android примет как обновление Starward. Поэтому ставь APK только из Releases этого репо.

## Как перенести в GitHub Secrets (когда захочешь)

Важно: в секреты кладётся **этот же** ключ, а не новый. Новый ключ = обновления больше не встанут, только через удаление игры.

1. `Settings → Secrets and variables → Actions → New repository secret`, три секрета:
   - `ANDROID_KEYSTORE_BASE64` — base64 от `signing/release.keystore` (одной строкой);
   - `ANDROID_KEYSTORE_PASSWORD` — `password` из `signing/keystore.properties`;
   - `ANDROID_KEY_ALIAS` — `starward`.
   base64 можно попросить сделать Claude — он пришлёт строку.
2. Запушить что угодно в `main` и в логе шага «Prepare signing key» увидеть `Signing key: GitHub Secrets`, а шаг «Verify signature» должен быть зелёным (отпечаток совпал).
3. Скачать `signing/release.keystore` и `keystore.properties` себе в облако как бэкап, затем удалить их из репо.
   (Из истории git они никуда не денутся — для полной зачистки после переезда надо будет и ключ, и отпечаток считать скомпрометированными только в теории; на практике для личной игры это ок.)

CI выбирает так: если все три секрета заданы — берёт их, иначе — файл из `signing/`. Ключ в CI никогда не генерируется.

## Проверка

В описании каждого релиза есть строка `Подпись SHA-256: …` — она одинаковая во всех релизах и совпадает с `signing/cert_sha256.txt`.
